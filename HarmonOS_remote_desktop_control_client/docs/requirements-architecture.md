# 第二章 概要设计

## 1. 功能模块分解

HarmonyOS 远程桌面控制客户端总体采用四层结构：用户界面层、业务逻辑层、网络通信层和数据配置层。用户界面层负责连接入口、远程屏幕展示和操作反馈，业务逻辑层负责会话管理、控制命令、画面处理以及断线重连策略，网络通信层负责 TCP/HTTP 连接、消息收发和数据编解码，数据配置层负责本地配置存储、会话缓存和日志状态。

用户界面层与业务逻辑层之间存在直接交互：用户的连接请求、鼠标键盘控制和剪贴板操作由 UI 层传递给业务逻辑层；业务逻辑层将状态更新、操作结果和远程画面反馈回 UI 层。业务逻辑层与网络通信层之间也存在双向通信关系：业务逻辑层向通信层发送远程控制命令和画面请求，通信层将网络返回的数据传递回业务逻辑层并提供连接状态信息。业务逻辑层与数据配置层之间存在读写关系：会话管理和连接配置需要读取本地配置，运行过程中产生的会话缓存和日志状态需要写入本地存储。

## 2. 模块层次结构

前端显示层包括首页/设备连接、远程屏幕页和设置/日志页面。首页/设备连接页面负责输入目标设备地址、发起连接和显示当前连接状态；远程屏幕页负责远程画面显示、触控交互和控制面板；设置/日志页面负责网络参数配置、画质调节、重连策略和日志查看。前端显示层与核心逻辑层直接关联：页面控件将用户操作传递给会话管理与控制命令模块，核心逻辑层将连接状态、画面更新与操作反馈返回给界面。

核心逻辑层由会话管理、控制命令、画面处理和剪贴板/文件传输模块组成。会话管理模块负责建立和维护远程连接、处理重连逻辑和会话状态，并协调本地配置和运行时缓存；控制命令模块负责将用户输入转化为远程控制指令并发送给通信层，同时接收通信层的执行结果反馈给 UI 层；画面处理模块负责解码远程屏幕数据、压缩与解压策略以及画面展示优化，支持远程屏幕页的高效显示；剪贴板/文件传输模块负责同步剪贴板内容和传输文件的请求与结果。

通信层由 TCP 客户端、HTTP 客户端和数据编解码模块构成。TCP 客户端负责建立与远程服务端的长连接、发送控制命令和接收屏幕数据，作为业务逻辑层与远程设备之间的主通道；HTTP 客户端负责处理短链接请求、获取配置或设备信息，支持设置页面的辅助请求；数据编解码模块负责对远程传输数据进行编码与解码，确保网络传输效率和数据完整性，并为画面处理和控制命令提供可靠的数据格式。

存储层包括本地配置和状态缓存。本地配置用于保存用户的连接参数、历史设备列表和默认设置，供会话管理模块读取；状态缓存用于临时存储当前会话数据、连接状态和运行日志，便于快速重连、故障定位和恢复页面状态。

## 3. 调用关系与接口

整个流程从用户发起连接开始：用户在 UI 层输入服务器地址并发起连接，UI 层调用业务逻辑层的 `requestConnect` 接口进行连接初始化。业务逻辑层读取本地配置，调用网络通信层的 `openTcpConnection` 接口建立 TCP 连接。通信层返回连接结果后，业务逻辑层将连接状态回传给 UI 层以更新页面显示。

在远程交互过程中，用户在远程屏幕页进行鼠标或键盘操作，UI 层将事件传递给业务逻辑层，业务逻辑层将事件封装为远程控制命令并调用通信层发送。通信层负责将命令发送到远程服务端，并将服务端的回执或错误信息返回给业务逻辑层。业务逻辑层根据回执更新 UI 层的控制状态。

远程画面获取过程由通信层负责接收屏幕数据，业务逻辑层调用 `decodeFrame` 接口对接收到的原始数据进行解码与渲染，然后将渲染结果回传 UI 层进行显示。

在剪贴板和文件传输场景中，UI 层将用户触发的辅助操作请求传递给业务逻辑层，业务逻辑层调用通信层传输辅助数据，通信层将操作结果返回给业务逻辑层，最终业务逻辑层将结果反馈回 UI 层。通过这种多层调用关系，系统实现了界面交互、业务调度、网络通信和本地存储之间的清晰分工。

### 模块接口说明

- UI 层
  - `requestConnect(serverInfo)`：接收服务器地址和端口，发起连接请求。
  - `sendControlEvent(event)`：接收用户输入的鼠标、键盘事件并转发给业务逻辑。

- 业务逻辑层
  - `openTcpConnection(server)`：根据服务器信息建立 TCP 连接。
  - `transmitRemoteCommand(cmd)`：将控制命令发送给网络通信层。
  - `decodeFrame(data)`：对接收到的远程屏幕数据进行解码并生成渲染帧。

- 网络通信层
  - `send(data)`：发送已编码的数据到远程服务端。
  - `onMessage(callback)`：注册消息回调，处理通信层接收的原始网络数据。

- 存储层
  - `loadConfig()`：读取本地配置和历史连接参数。
  - `saveSession(info)`：保存会话数据、连接状态和日志信息。

## 4. 人机界面与交互重点

用户界面设计应突出简单操作和状态反馈，重点包括：

- 主页：输入远程设备地址、选择连接方式、显示当前会话与连接状态。
- 远程屏幕页：实时画面展示、控制工具栏、断开/重连按钮、响应用户触控与键盘输入。
- 设置页：网络参数配置、图像质量调节、重连策略选择、日志与状态查看。
- 提示反馈：连接成功/失败、操作执行结果、异常提醒、重连提示。

## 5. 概要说明

本系统采用“前端显示层 -> 核心逻辑层 -> 通信层 -> 存储层”四层架构。用户的每一次操作首先经过 UI 层，由业务逻辑层进行调度和策略判断，再通过通信层与远程设备进行数据交互，最后将结果反馈给界面。模块之间以接口调用为核心交互方式，确保了职责清晰、可扩展性高和后续维护便捷。
