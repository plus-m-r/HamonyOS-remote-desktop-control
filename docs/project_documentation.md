# 远程桌面控制项目技术文档

## 1. 项目概述

### 1.1 项目背景与意义

随着移动设备的普及和远程办公需求的增加，远程桌面控制技术变得越来越重要。本项目旨在开发一个跨平台的远程桌面控制系统，支持从HarmonyOS设备和Java客户端远程控制Windows/Mac/Linux等操作系统的计算机。

主要应用场景包括：
- 远程办公与技术支持
- 远程教学与培训
- 跨设备协作
- 远程服务器管理

### 1.2 主要功能特性

- **跨平台支持**：服务端支持Windows、Mac、Linux；客户端支持HarmonyOS和Java
- **高效屏幕捕获**：基于tile的分块捕获，减少数据传输量
- **智能压缩算法**：结合ZSTD压缩和RLE编码，平衡传输速度和质量
- **实时响应**：优化的网络传输和异步处理，确保流畅的用户体验
- **多客户端支持**：服务端可同时处理多个客户端连接
- **安全通信**：基于TCP协议的可靠数据传输

## 4. 网络通信协议

### 4.1 协议设计

- **消息格式**：二进制格式，固定头部 + 可变长度数据
- **命令类型**：请求命令和响应命令
- **数据编码**：小端字节序

### 4.2 消息格式

| 字段 | 长度 | 描述 |
|------|------|------|
| 魔数 | 4字节 | 固定值0xDEADBEEF |
| 版本 | 1字节 | 协议版本号 |
| 命令类型 | 2字节 | 命令类型编码 |
| 数据长度 | 4字节 | 后续数据的长度 |
| 数据 | 可变 | 命令具体数据 |

### 4.3 命令类型

| 命令类型 | 编码 | 方向 | 描述 |
|----------|------|------|------|
| ReqCapture | 1 | 客户端→服务端 | 请求屏幕捕获 |
| ResCapture | 2 | 服务端→客户端 | 屏幕捕获响应 |
| ReqMouse | 3 | 客户端→服务端 | 鼠标事件 |
| ReqKeyboard | 4 | 客户端→服务端 | 键盘事件 |
| ReqPing | 5 | 客户端→服务端 | 心跳请求 |
| ResPong | 6 | 服务端→客户端 | 心跳响应 |

### 4.4 数据传输流程

1. 客户端建立TCP连接
2. 客户端发送ReqPing命令
3. 服务端返回ResPong命令
4. 客户端发送ReqCapture命令
5. 服务端执行屏幕捕获
6. 服务端压缩捕获数据
7. 服务端发送ResCapture命令
8. 客户端解压数据并显示
9. 重复步骤4-8

## 5. 数据处理流程

### 5.1 屏幕捕获流程

1. 服务端接收ReqCapture命令
2. ScreenCaptureService获取屏幕尺寸
3. 将屏幕划分为多个tile
4. 对每个tile进行捕获
5. 与上一帧比较，标记变化的tile
6. 生成捕获数据结构

### 5.2 压缩与解压流程

**压缩流程**：
1. 对每个变化的tile进行RLE编码
2. 对编码后的数据进行ZSTD压缩
3. 生成压缩数据包

**解压流程**：
1. 接收压缩数据包
2. 进行ZSTD解压
3. 对解压后的数据进行RLE解码
4. 重建屏幕图像

### 5.3 图像传输流程

1. 服务端将压缩数据封装为ResCapture命令
2. 通过TCP连接发送给客户端
3. 客户端接收并解析命令
4. 提取压缩数据

### 5.4 显示流程

**HarmonyOS客户端**：
1. 解压数据
2. 构建Capture对象
3. 创建图像缓冲区
4. 调用PixelMap API创建图像
5. 在UI组件中显示

**Java客户端**：
1. 解压数据
2. 构建BufferedImage
3. 在Swing组件中显示

private async processCaptureTask(task: any): Promise<void> {
  try {
    const { cmd, imageData, compressionMethodOrdinal } = task;
    
    // 1. 解压数据
    const unzippedData = await this.decompressData(imageData, compressionMethodOrdinal);
    
    // 2. 解析Capture对象
    const capture = await this.compressor.decompress(this.tileCache, unzippedData);
    
    // 3. 构建图像缓冲区

    // 4. 传递给UI

      this.screenCallback(imageBuffer.buffer, capture.width, capture.height, Date.now());
    }
    
    // 5. 保存前一帧信息
    this.prevImageBuffer = imageBuffer;
    this.prevImageWidth = capture.width;
    this.prevImageHeight = capture.height;
    
  } catch (error) {
    console.error('RemoteControlService: Failed to process capture task', error);
  }
}

### 11.3 压缩算法原理

#### ZSTD压缩

ZSTD（Zstandard）是一种快速无损压缩算法，由Facebook开发。它的特点是：
- 压缩速度快，解压速度更快
- 压缩率接近DEFLATE，但速度更快
- 支持字典压缩，进一步提高压缩率
- 内存占用低

#### RLE编码

RLE（Run-Length Encoding）是一种简单的无损数据压缩算法，它的原理是：
- 对于连续相同的数据，只存储一个数据值和它的重复次数
- 适用于有大量连续重复数据的场景
- 实现简单，解码速度快
