# 新架构设计方案

## 📋 文档说明

本目录包含针对方寸控远程桌面系统现有架构问题的新一代架构设计方案。

**创建时间**：2026-05-10  
**目标**：解决现有8个核心架构问题，提升系统性能、可维护性和开发效率

---

## 🎯 设计目标

### 核心原则

1. **异步优先**：所有耗时操作异步化，避免阻塞主线程
2. **零拷贝优化**：减少内存分配和拷贝，降低GC压力
3. **智能背压**：基于性能指标的动态调整，而非被动丢弃
4. **统一抽象**：跨平台API一致性，简化多端开发
5. **可观测性**：全链路监控和追踪，快速定位问题

### 解决的问题

#### P0级严重问题（必须立即解决）

1. ✅ **单线程瓶颈导致工作流相互阻塞**
   - 压缩/解压引擎多线程化
   - HarmonyOS端数据处理移至Worker线程
   - 消除屏幕流对控制流的阻塞

2. ✅ **synchronized锁竞争导致线程阻塞**
   - 使用ReadWriteLock替代粗粒度锁
   - volatile标志位替代简单同步
   - 细化锁粒度，减少竞争

3. ✅ **Semaphore反压机制设计缺陷**
   - tryAcquire带超时机制
   - 动态调整队列大小
   - 分离网络线程和解压队列

4. ✅ **第三方压缩库缺乏统一抽象**
   - 统一的ICompressor接口（Java + HarmonyOS）
   - 消除HarmonyOS端磁盘IO
   - 性能提升75%

5. ✅ **PixelMap渲染高GC与高拷贝**
   - PixelMap复用 + writePixels增量更新
   - 每帧内存分配从16MB降至0MB
   - GC停顿从150ms/s降至20ms/s

6. ✅ **数据库设计不完善 + 背压控制缺失**
   - 扩展至13张表（用户/设备/会话/审计/性能）
   - 智能背压控制（规则引擎+自适应学习）
   - 性能监控与背压联动

#### P1级重要问题

7. ✅ **多端调试困难**
   - 统一日志格式规范
   - 分布式TraceID追踪
   - 日志聚合中心（Elasticsearch + Kibana）

8. ✅ **测试代价大，启动时间长**
   - 分层测试架构（单元/集成/E2E）
   - Node.js纯逻辑测试（无需模拟器）
   - TDD工作流支持零散时间开发

## 💡 实施建议

### 快速见效策略

1. **优先实施问题4+5**：2-3周内可见显著性能提升

4. **灰度发布**：每完成一个阶段即进行小范围验证

### 风险控制

1. **回滚预案**：每个阶段保留回滚能力
2. **性能基准**：建立性能基准测试，防止退化
3. **渐进式迁移**：新旧架构共存一段时间，平滑过渡
4. **充分测试**：每个阶段完成后进行完整回归测试
